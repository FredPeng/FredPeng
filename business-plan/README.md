# 肯尼亚跨境电商 —— 商业计划评审与修订

模式约束（用户设定）：**不做 COD，全额预付；本地不备货；只做跨境。**

**物流模式**：国内集货 —— 多个订单合并成一个大包裹整批空运，肯尼亚收货后拆包、
重新打包、分发给各客户。运费 **USD 12/kg 线性计价、含税（双清包税）**，**抛货比 5000**。

---

## 优化版商业计划

原计划的结构保留。**两处原计划做对了的地方，优化建立在其上：**

- **标准 ①②（图片数、视频质量）不是在挑好看的，是在筛"素材可得性"** —— 直接决定广告测试成本。
- **标准 ④ 用速卖通价格做比较**，真正作用是**校验采购成本是否合理**。直觉正确，
  但用错了位置 —— 它该做筛选条件，不该做定价目标。

---

### 步骤 0（新增）：先锁 1–2 个品类方向

原计划全品类撒网。跨境一件代发下这很吃亏 —— 同类目的品能共用供应商、共用运费议价、
共用受众与像素数据、共用落地页模板。**全品类撒网 = 每个品从零开始，广告像素永远学不到东西。**

这是提高中签率最便宜的办法，零成本。

### 步骤 1：选品

**Temu 与速卖通分工使用（对原计划的直接增强）：**

- **Temu 用来发现品** —— 其推荐流本身是需求验证机器，能被算法推上首页的，转化率已被验证。
- **速卖通用来拿素材 + 校验成本** —— 原标准 ①②④ 全部放在这一侧。

**修订后的标准：**

| 原标准 | 改成 | 原因 |
|---|---|---|
| ③ 售价 ≥ 2,000 KES | **由 CPA 决定**：最低售价 ≈ (CPA + 170) ÷ 0.32<br>CPA 2,400 → 8,000；CPA 1,200 → 4,300 | 集货线性计价下运费不再是价格下限的决定因素，**CPA 才是**（见下） |
| ④ 加 40% 毛利、价格 ≈ 速卖通 | **筛选条件**：落地成本 ≤ 速卖通售价 × 55%<br>**定价**：落地成本 × 3 | 把速卖通从"定价目标"改为"成本校验基准" |
| ①② 图片视频 | 保留，**降为加分项** | 决定投放成本，不决定这个品能不能卖 |

**新增（均为页面上可直接查看、零成本）：**

5. **重量/体积上限** —— 按目标售价倒推，见 `--table` 速查表
6. **速卖通评论数 + 近 90 天评论占比** —— 评论数是真实销量代理；近期占比高 = 上升期。**只做上升期的品**
7. **同款卖家数**（搜同图）—— 卖家多 = 素材烂大街、竞争激烈；**卖家少但有销量 = 最优区间**
8. **变体 ≤ 2 个，供应商 ≥ 2 家** —— 零备货下断货 = 已收款却交付不了

**售价下限 = f(CPA)**（`--floor`）—— 集货模式下运费不再决定价格下限：

```
       CPA        贡献率25%      贡献率30%
       800           3,031         3,593

     3,000           9,906        11,741
```

> **战略含义：降低 CPA 会直接打开低价品的可做区间。**
> 老客复购 / WhatsApp 私域 / 自然流量原本是"锦上添花"，在集货模式下是**扩大选品池的杠杆** ——
> CPA 从 2,400 降到 1,200，可做价格带下沿从 8,000 掉到 4,300，候选品数量翻数倍。

**⚠️ 体积是第一约束**。抛货比 **5000**：`长×宽×高(cm) ÷ 5000 = 计费重(kg)`，与实重取大者。

> **每 1kg 实重只配 5 升体积**（5 升 ≈ 25×20×10cm）。绝大多数带零售彩盒的消费品都超标。
> **集货模式下，运费实际是按"箱子多大"收的，不是按"东西多重"收的。**

**压缩体积值 5,471 KES/件 —— 比在 1688 上砍价能省的多得多。**

#### 新增选品维度：可压缩性

| | 例子 |
|---|---|
| ✅ 好 | 软质、可压缩、可折叠、可拆卸、可平铺 —— 纺织品、包袋、织物、窗帘、可折叠家居 |
| ❌ 差 | 刚性中空 —— 塑料收纳箱、桶盆、头盔、鞋、带模压泡沫的、异形不可堆叠 |

> 一个塑料收纳箱在 1688 上或许只要 ¥30，但 40×30×30cm 的运费即 11,318 KES —— **永远做不了**。

#### 采购端动作（比仓库端更有效）

在下单时解决，而非到货后补救：

1. **要求 1688 供应商发散装 / 裸货**，不带零售彩盒 —— 多数供应商有散装出货选项，尤其纺织与家居软货
2. **软货用真空压缩袋** —— 体积可砍 50–70%
3. 说明书、保修卡、配件独立归集，不逐件塞箱占体积

> 反正肯尼亚要拆包重打，**1688 的零售包装对你零价值，但你在为它付 1,572 KES/kg 的空运费。**

### 步骤 2：上架

原计划为"重写标题和 Specification"，但未定目标。定了目标效果差很多：

**标题为 Google 搜索而写，不是为好看而写。** 预付 + 跨境模式下 Google 高意图流量最匹配，
且这部分免费。格式：`[肯尼亚人实际会搜的品类词] + [关键规格] + Price in Kenya`

**Specification 要承担说服工作** —— 零备货预付模式下，产品页需替你回答"凭什么先给你钱"：

- 具体送达日期区间（不是"10–15 天"）
- M-Pesa 付款标识
- 可打通的电话 / WhatsApp
- 本地同类价格对比（贵得有理的依据）

后三项**做成模板，一次写好全站复用** —— 原计划没有、但成本最低的转化率改善。

**图片不要直接搬详情图** —— 速卖通详情图常含其他卖家品牌、别国货币、不适用于肯尼亚的承诺。
批量处理：去水印 → 统一比例 → 加 KES 价格角标。

### 步骤 3：投放

**"在各个广告平台上投放"是原计划最该改的一条。** 分散投放让每个平台的像素都学不到东西，
且无法归因。**测试期集中一个平台。**

**按品的性质分流渠道：**

| 品的性质 | 渠道 | 逻辑 |
|---|---|---|
| **已知品类**（本地买得到但贵） | Google 搜索 / 购物 | 客户已在找，高意图，预付阻力最小 |
| **新奇品**（没人见过） | Meta / TikTok 视频 | 需求由广告创造 |

> 新奇品本来就不该有搜索信号 —— 它走发现型流量。**用搜索量去筛新奇品是错的。**

**素材加工的最低限度**：速卖通视频通常没有 hook，而前 3 秒定生死。
剪 3 个不同开头 + 加 KES 价格 + 加字幕，就这三件事。

**转化事件设为"付款成功"**，不要设"加购"或"发起结账"。预付模式下每个购买事件都是真钱 ——
这是相对 COD 玩家的结构性优势，算法学习效率不是一个量级。原计划没提，但这是免费的。

**固定测试协议**（以毛利为单位，不用绝对金额）：

- 每品测试预算 = **2 × 单件毛利**，跑 3–5 天
- 花到 1× 毛利仍无加购 → 关
- 花到 2× 毛利仍无付款单 → 关
- 出 2 单且 CPA < 毛利 40% → 加预算
- **并行测 10–20 个品，不要串行**

### 步骤 4（新增）：加购与并单

**更正**：早前版本称并单为"运费套利" —— 那只在单票小包的首重结构下成立。
**集货线性 $12/kg 下，并单不省任何跨境运费。**

加购与组合装仍是本模型下最直接的利润来源，但理由变了：**摊薄 CPA**。
一单卖两件，CPA 直接减半 —— 按上文"售价下限 = f(CPA)"，这才是真正的杠杆。

- 每个主品配 1–2 个**低体积高毛利加购品**
- 满额免运费门槛设在客单价的 **1.3–1.5 倍**
- 同客户 48 小时内订单并单发货 —— 仍值得做，但只省肯尼亚端最后一公里（约 350 KES/单）

### 步骤 5（新增）：批次风险切分

集货意味着**一个大包裹里装着几十个已付款客户的货**。扣关、丢件、延误都是几十人同时出事，
而钱已经收了 —— 这是本模式最尖锐的相关性风险。

**对策：同一批次拆成 2–3 个包裹分开走**，不要把一周的订单放进一个箱子。
成本增加有限，但把"全灭"变成"损失三分之一"。

### 步骤 6（新增）：VAT 与清关路径

**已确认**：$12/kg **含税**（双清包税）。因此落地成本中税费计 0，本文档各表成立。

**但双清包税拿不到你公司名下的 KRA 进口报关单 => 无进项 VAT 可抵。**

肯尼亚 VAT 注册门槛为**年营业额 500 万先令** —— 按 12,000 KES 客单，约 **35 单/月** 即触及。
注册后须对销售收 16% 销项 VAT，而无任何进项可抵，16% 全额从利润里出：

| ¥175 / 0.8kg，售价 12,000 | 贡献额 | 贡献毛利率 |
|---|---|---|
| 未注册 VAT | 3,882 | 32.4% |
| 注册后（双清包税，无进项） | **2,227** | **18.6%** |

> 每单少赚 1,655 KES，贡献毛利率掉 14 个点。**月流水 42 万先令即触线** —— 这不是遥远的事。

**双轨策略（与"零备货起步、winner 加深度"的节奏一致）：**

- **测试品走双清包税** —— 快、灵活、无合规成本
- **winner 转正规清关** —— 拿到本公司报关单即可抵进项，抵消这 16%；
  同时解锁开具正规发票、销售给 B2B 客户。
  代价：关税 + VAT + IDF + RDL 需自行核算、需报关行、需 KEBS PVoC，只有单品量大才摊得平。

用 `--vat` 开关对比两种情形。

# 附录：分析过程

以下为得出上述参数的推演与市场分析，供追溯。

### 附 1、原计划的核心问题

原计划的选品标准（速卖通有销量、图 ≥6 张、详情图 ≥10 张、有好视频、售价 ≥2,000 KES、
1688 有货且加 40% 毛利后价格与速卖通持平或更低）存在三个结构性问题：

#### 1. 全部是供给侧信号，没有需求侧信号
标准问的是"这个商品好不好拍、好不好上架"，没有一条问"肯尼亚人现在买不买"。
图好看的滞销品到处都是。

#### 2. 40% 毛利在任何一种付款模式下都不够
- COD 模式：RTO（拒收）20–35%，每个拒收单亏广告费 + 双程运费。RTO 超过约 22% 时 40% 毛利归零。
- 预付模式：冷流量转化率只有 COD 的 1/3–1/5，CPA 上涨 2–4 倍，把省下的 RTO 全吃掉。

**亏损只是从 RTO 搬到了 CPA，没有消失。**

#### 3. 定价规则在一件代发结构下算不出来
一件代发的跨境运费是"首重 + 续重"结构，不是线性 $/kg。
按一件代发拿的是零售价、按票付首重，**运费可能是有规模的跨境卖家的 3 倍**。
样例：¥175 采购 / 0.8kg 的商品，落地成本 5,016 KES（≈¥271，物流杂费把成本推高 55%）——
要卖到 12,000 才有 30% 贡献毛利率。
（注：初版据此判定"打不过速卖通"，见下节修正 —— 成本结论成立，但速卖通并非肯尼亚的比价基准。）

### 附 2、竞争参照系（已修正）

**修正**：初版评审以速卖通为主要参照系和竞争者，这个前提是错的 —— 速卖通在肯尼亚渗透率低，
并非本地消费者的默认比价对象。

- **成本结论不变**：一件代发的落地成本由"首重+续重"的运费结构决定，与速卖通无关。
- **对标价格改变**：基准不是速卖通价，而是**肯尼亚本地零售价**（常见为中国落地成本的 2–4 倍）。
- **因此定价空间打开，消费品路线重新成立。**

#### 真正的对标：Kilimall

2014 年中国人创立、总部内罗毕、第一家进入非洲的中国电商平台。模型与本计划高度重合：

| Kilimall 的做法 | 对本计划的意义 |
|---|---|
| **坚持先付款再发货**（不同于其他平台的 COD） | 验证"全额预付"在肯尼亚可跑通 |
| Global Shopping：跨境代购直发肯尼亚 | 与本计划的消费品路线相同 |
| Kilibusiness：肯尼亚买家从中国批量采购 | 即下文路线 B，需求真实存在 |
| **同时建了"非洲海外仓"**（中国商家先发货到非洲仓，本地下单就近发货） | **最重要的信号，见下** |

> 一个模型几乎相同的公司跑了十年后加了备货 —— 大概率因为跨境直发的交付时长在消费品上撑不住。
> **零备货是必须主动管理的最大风险，不是可忽略的约束。**
> 折中路径：零备货起步（一件代发即低成本测试机制）→ **winner 转本地备货**。

#### 战略问题已改变

不再是"凭什么比速卖通强"，而是 **"凭什么比 Kilimall 强"**。
它有 1,000+ 服务站覆盖肯尼亚/乌干达/尼日利亚、摩托车配送、佣金 5–15%，
且与你同一条供应链、规模更大。**答案不可能是物流或价格。** 只剩两个方向：

1. **垂直 + 专业度** —— 它是大而全的货架平台；你做单一垂直，懂产品、能咨询、能售后。平台做不了深度。
2. **策展 + 内容 + 私域** —— 它是搜索框；你是"我帮你选好了"。靠 TikTok/WhatsApp 建立人对人信任。

注意：这两个方向恰恰都是 AI 帮不上核心忙的地方（产品知识、售后、人格化信任）。
**AI 放大定位，不创造定位。**

---

### 附 3、定位：品类缺口

**市场观察**：Kilimall 的跨境商品并不多 —— 计划中要卖的很大一部分，其平台上没有。

这给"凭什么比 Kilimall 强"一个具体答案：**品类覆盖**。你能触达整个 1688 长尾，平台只铺了很窄一条。

并且该定位连带解决了本文档前面标记的两个最大问题：
**当客户在肯尼亚找不到替代品时，预付阻力和价格敏感度同时大幅下降。**
无比价对象 → 65–70% 毛利可达成；无替代选择 → "先付款等 14 天"从"凭什么信你"变成"只能这样"。

#### 但必须先答对这个判断题

"平台上没有这个品"有两种相反解释：

- **A. 供给缺口** —— 供给链路够不到：SKU 太长尾、需要选品判断、单量小到平台不愿铺类目。**→ 机会**
- **B. 需求缺口** —— 在肯尼亚根本卖不动。**→ 陷阱**

不可忽视的先验：Kilimall 在肯尼亚跑了十年，有销售与搜索数据，知道什么卖得动。
**它没铺的品类里，B 的占比不低。**

支持 A 的理由：**平台经济学 ≠ 独立站经济学**。平台需要可规模化的 SKU —— 招商、类目建设、
客服培训的成本，长尾品类摊不平；且平台不做选品判断，靠卖家自行上架，本地中国卖家池有限。

> **真正的机会区间：需求真实存在、但单量不足以让平台专门去做的长尾品类。**
> 这也解释了为何 B2B/设备是最锋利的切口 —— 单价高、单量小、需咨询，平台结构上不适合做。

#### 区分方法：Jiji 是最好的探针

**Jiji 供给端零门槛** —— 无需供应链、无需类目审批，有货就能挂。因此它反映的是
**接近纯粹的需求信号**，不受供给能力扭曲。

- Jiji 上有人挂 / 有询价 / 有成交，但 Jumia、Kilimall 上没有 → **强供给缺口信号，最该做的品**
- Jiji 上也一片空白 → 大概率需求缺口，砍掉

交叉验证：

| 探针 | 供给缺口的表现 |
|---|---|
| Google 搜索量（KE） | 有搜索量，但结果全是国外站、无本地卖家 |
| Facebook 群 / WhatsApp 社交电商 | 有人在卖，或有人在问哪里能买到 |
| 本地实体零售 | 有店在卖但贵 2–4 倍（需求 + 价格空间同时确认） |
| 相邻品类 | 相邻品类卖得好、唯独此品空 → 偏供给缺口；整棵类目树都空 → 偏需求缺口 |

**⚠️ 此探针有已知缺陷，不可用于新奇品**：真正没人见过的品，在肯尼亚不会有任何需求信号 ——
没人会在 Jiji 上挂，也没人会去搜索。用"有需求信号"筛选会把最可能赚钱的一类品全部误杀。

**正确用法**：该探针仅适用于**已知品类**（本地买得到但贵）。
**新奇品走发现型流量（Meta/TikTok）验证，见正文步骤 3 的渠道分流。**

### 附 5、其他可选路线

#### 路线 A：本地备货 + 快交付 + 策展

（在修正竞争参照系后，A 与 B 不再互斥；A 可作为 B 或消费品路线跑出 winner 之后的演进方向。）
- 差异化：3 天送达 + 选品 + 本地售后
- 要求：压货、资金、仓库、COD 或预付均可
- 与"零备货"约束冲突

#### 路线 B：跨境 B2B / 大件设备

面向肯尼亚小微商户：商用厨房设备、美容院仪器、印刷切割设备、农业加工机械、
健身器械、建材五金等。

| 现有约束 | 在 B2B/大件上的表现 |
|---|---|
| 零备货 | 商业买家接受"下单 → 发货 → 4–6 周"，是行业惯例 |
| 全额预付 | 商业采购本就付 30–50% 定金甚至全款；理性买家 |
| 跨境运费高 | 客单 50,000–500,000 KES，运费占比个位数，甚至可走海运 |
| CPA 高 | 单笔利润数万先令；Google 搜索意图极强 |
| 打不过速卖通 | 速卖通不做此类 —— 运费与售后结构不支持 |
| 打不过本地 | 本地设备商加价常达 2–4 倍且款式陈旧 |

附加优势：**口碑与复购**。一个餐馆老板用得好会告诉另外五个。消费品一件代发没有这个。

代价：需要产品知识、售前咨询、装机/维修支持、销售周期长、订单密度低。
**但这些正是壁垒 —— 因为难，所以没人做。**

#### 若坚持消费品路线，唯一活法
只做"速卖通上有、但肯尼亚人搜不到 / 不敢买 / 挑不出来"的高客单品（≥12,000 KES），
靠内容和 WhatsApp 建立信任，明确定位为代购。
天花板取决于内容能力，不是供应链能力。

### 附 6、选品标准（完整版）

原标准中的"图 ≥6 张、详情图 ≥10 张、有好视频"应从**准入标准降级为加分项** ——
它决定投放成本，不决定这个品能不能卖。

1. **本地买不到，或本地价 ≥ 中国落地成本 2.5 倍**（最重要，取代"图片好看"）
1b. **且需求信号已被证实**：Jiji 有挂牌/询价，或 Google KE 有搜索量，或社交电商有交易痕迹。
    三处均无痕迹 → 直接砍掉（区分供给缺口与需求缺口，见附 3）
2. 售价 ≥ 12,000 KES（消费品路线）—— 基准是**肯尼亚本地零售价**，不是速卖通价
3. 运费占售价 ≤ 12%（按首重+续重实算，不是线性 $/kg）
4. 加价 ≥ 2.9 倍落地成本（毛利率 65–70%），定价对标**本地零售价的 60–80%**
5. 低故障率：不易碎、无尺码、无活动部件、非复杂电子（零备货 = 无法换货）
6. 类目可过关：无电池/液体/磁铁/仿牌；KEBS PVoC 可覆盖
7. 1688 有 ≥2 家可用供应商（单一供应商不做）
8. 需求信号：KE 地区 Google 搜索量 + Jumia/Kilimall 评论数 + Meta 广告库投放时长
9. （加分）图片/视频素材质量

### 附 7、运营要点

#### 链路：别让 1688 供应商直发出境
```
1688 一件代发 → 中国转运仓（开箱验货拍照 + 换外箱 + 贴单）→ 跨境专线 → 肯尼亚最后一公里
```
零备货意味着转运仓是**唯一的品控检查点**。供应商直发 = 把品控彩票寄给已付款客户，
14 天后才知道开出什么。转运仓 ¥2–5/件，是刚性成本。

#### 头号风险：相关性风险
零备货 + 预付模式下，问题不会一个一个来，会一批一批来：
- 一票货扣关 → 同批几十个已付款客户同时要退款，而货款运费已付
- 供应商发错版本 → 14 天后、8,000 公里外才发现，无本地库存可换

对策：养 2–3 条货代线；中国端强制验货；预留 **5–8% 赔付准备金**。

#### 交付承诺工程化
- 固定发运班期（每周两班），结账页显示**具体日期区间**而非"10–15 天"
- 每 3 天一条 WhatsApp 进度推送 —— 多数退款要求源于焦虑而非不满
- 同客户 48 小时内订单**自动并单**（一票只付一次首重，是实打实的运费套利）

#### 获客
冷流量直接进结账页在预付模式下转化极低。可行的两条：
1. **Google Search / Shopping** —— 高意图流量，与预付模式最匹配，权重应高于 Meta
2. **广告 → WhatsApp → 对话 → M-Pesa 付款链接** —— 信任在对话里建立，不在落地页上

#### 技术优先项
WooCommerce 接 **Daraja API STK Push**。若当前是"转账到 Paybill 再粘贴交易码"，
这一步在流失大量已决定购买的客户。

### 附 8、扩量公式

> **月利润 = 每月测试数 × 中签率 × 单个 winner 的生命周期利润**

一件代发的最大战略价值：零 MOQ、零压货，把第一个乘数的资金约束几乎去掉 ——
**可以同时测 50 个品而不是 5 个**，瓶颈只剩广告测试预算。

- 提高测试数：固定小额预算（$60–100 / 3 天）+ 固定模板 + 固定 kill 规则，**并行测不要串行测**
- 提高中签率：需求侧信号 + 把自己的历史 winner/loser 数据回灌到打分模型
- 提高 winner 深度：提价测试、组合装（同时是运费套利）、多渠道、**WhatsApp 私域复购**

### 附 9、AI 能接管的部分

#### 首要应用：品类缺口扫描器

若核心竞争力是"覆盖别人没有的品类"，则核心能力是**发现缺口的广度与速度** ——
这是 AI 唯一能提供数量级提升的环节。**它比改写标题、生成素材重要得多。**

```
1688 类目批量抓取（候选池，数万 SKU）
   ↓ 硬过滤（价格 / 重量 / 类目黑名单 / 价值密度）
   ↓ 供给侧反查：Jumia / Kilimall / Jiji / 本地零售 —— 有没有人在卖？多少钱？
   ↓ 需求侧反查：Google KE 搜索量 / Jiji 挂牌与询价 / 社交电商痕迹
   ↓ 打分：需求信号强 × 本地供给弱 × 落地成本可行 × 低故障率
   ↓ 输出：Top N 缺口品 + 逐个落地成本与建议售价（接 tools/unit_economics.py）
```

手工一天能查 20 个品；自动化后一天可扫 2,000 个。

**复利效应**：运行一段时间后积累"哪些缺口品真的卖动了"的历史数据，回灌打分模型，
中签率持续上升。**这是平台模式拿不到的数据。**

#### 其余环节

**可自动化 ~70%，但自动化的是执行，不是判断。**

| 环节 | 自动化程度 | 说明 |
|---|---|---|
| 采集 | 高 | 优先官方 API（速卖通联盟/DS API、1688 开放平台图搜），纯爬虫有 ToS 与封 IP 问题 |
| 硬过滤 | 高 | 价格/重量/类目黑名单 —— 是规则，不需要 AI |
| 图片视频质量判断 | 高 | 多模态打分、水印检测、主图与详情一致性 |
| 1688 反查比价 | 高 | 图搜找同款 → 多供应商比价 |
| 落地成本与定价 | 高 | 见 `tools/unit_economics.py` |
| "肯尼亚人会不会买"打分 | 中 | 需用自己的历史数据 few-shot 校准，否则是瞎猜 |
| 上架（标题/规格/SEO/图片/写入 WooCommerce） | 很高 | 一人 + 脚本一天 200–500 SKU |
| 广告素材与文案 | 中 | 适合第一轮测试；winner 必须换本地实拍 UGC |
| 投放杀/放量决策 | 高 | **用确定性规则引擎，不要用 LLM 决策** |
| WhatsApp 成交与客服 | 高 | 预付模式下 WhatsApp 是成交渠道不是客服渠道，ROI 最高 |

**AI 做不了的（也就是真正的护城河）**：现金、货代关系与清关、COD/配送商谈判、
退货处理、KEBS/KRA 合规、本地客户信任、winner 的本地实拍素材、B2B 路线的产品知识与售后。

> AI 能把"每周测 3 款"变成"每周测 30 款"，成本几乎不变。
> 但它不解决毛利率、交付确定性和定位问题 —— 而那三个才是生死线。

## 候选品类：约束反推出的画像

参数锁定后（$12/kg 含税、抛货比 5000、CPA 2,200），可行区间非常窄：

```
货值        ¥80 – 180
计费重      <= 0.9kg  ->  体积 <= 4.5 升（约 25x15x12cm）
售价        8,000 – 14,000 KES
本地零售    >= 售价 / 0.85
```

### 关键发现：模型与肯尼亚线上最大品类不重合

`business-plan/candidates.csv` 中 16 个品类原型跑筛，砍掉 5 个 —— **而这 5 个恰好是
肯尼亚线上销量最大的品类**（服装与鞋类是肯尼亚线上购物最热门的两类，服装为 Jumia 订单量
最大的单一品类；手机配件是利润率最高的进口品之一）：

| 砍掉 | 直接原因 | 结构性原因 |
|---|---|---|
| 女装连衣裙 | 运费 17% + 变体过多 | 尺码 → 零备货无法换货；服装同时抛货 |
| 手机壳 / 充电线 | 变体过多 | 客单 < CPA 下限，**永远不可能** |
| 厨房塑料收纳 | 运费 30% | 刚性抛货 |
| 便携太阳能板 | 运费 20% | 又重又大 |
| 智能手表 | 变体过多 | 竞争极烈、假货认知问题 |

> **不能跟着"肯尼亚最好卖的东西"这类榜单走** —— 那些榜单是给有本地库存、做 COD、
> 卖低客单的玩家写的。本模型必须去销量不是最大、但价值密度高的地方。

### 通过筛选的三簇

**A. 美容美发** —— 真人发/HD 假发、IPL 脱毛仪、射频美容仪、无线电推剪、高温直发梳
> 肯尼亚最强消费品类之一。客单高、复购高、**无尺码问题**、多为软件小件。
> 假发提示"抛货 2.4x" —— 先确认供应商能否真空压缩发散装，能压下来即是最匹配的一个。

**B. 专业工具** —— 激光测距仪、OBD 诊断仪、工业内窥镜
> Google 高意图搜索、买家理性、耐用低故障、**天然接受预付**。单量小，正是平台不愿铺的长尾。

**C. 健康设备** —— 数字血压计
> 刚需 + 耗材复购。需先确认 KEBS 医疗器械合规。

### ⚠️ 当前排序不可信

需求信号三列（reviews / reviews_90d_pct / sellers）留空，评分仅反映经济性。
典型反例：无线耳机排第一是假象 —— 经济性好，但建议售价 6,514 已高于速卖通 5,500、
逼近本地零售 9,500，且该品类在肯尼亚遍地都是。

**下一步**：从 A、B 两簇各挑 3–4 个具体品，去 1688 与速卖通填入真实采购价、外箱尺寸、
评论数、近 90 天占比、卖家数，重跑筛选。那一次的输出才是可下单的清单。

**`candidates.csv` 中的采购价与尺寸均为按品类常识的估值，必须以真实数据替换。**

## 自动化路线图

**原则：AI 做执行，规则做判断。** 凡是要花钱的决策（杀量 / 放量 / 采购）一律用确定性规则引擎，
不要交给 LLM。

| # | 环节 | 可自动化 | 状态 | 阻塞 |
|---|---|---|---|---|
| 1 | 选品硬过滤 + 定价 | 100%（纯规则） | ✅ `tools/screen.py` | — |
| 2 | 上架生成（标题/规格/SEO/FAQ/WooCommerce CSV） | ~90% | ✅ `tools/listing.py` | 需 API key |
| 3 | 选品数据采集（1688 价格尺寸、速卖通信号） | ~60% | ⬜ | 需官方 API 或采集方案 |
| 4 | 图片处理（去水印、统一比例、加 KES 角标） | ~95% | ⬜ | **无阻塞，下一个该做** |
| 5 | 广告素材加工（剪 3 个 hook、加字幕、加价格） | ~70% | ⬜ | **无阻塞，需 ffmpeg** |
| 6 | 投放杀/放量决策 | 100%（规则引擎） | ⬜ | 需广告平台 API |
| 7 | WhatsApp 成交 + 客服 | ~80% | ⬜ | 需 WhatsApp Business API |
| 8 | 订单 → 1688 采购 → 集货 → 进度通知 | ~70% | ⬜ | 需 1688 下单接口 |

**优先级建议**：先做 4 和 5（无外部依赖，直接降低每个品的测试成本），
7 的 ROI 最高（预付模式下 WhatsApp 是成交渠道不是客服渠道）但要先申请 API。

### `tools/listing.py` 的设计要点

- **标题为 Google 搜索而写**，不是为好看 —— 肯尼亚人搜什么词就用什么词 + "Price in Kenya"
- **信任模块、交期、M-Pesa 标识由代码确定性拼接**，全站统一，不交给模型（改 `SHIPPING` 和
  `TRUST_BLOCK` 即全站生效）
- **模型额外输出两样筛选期就该知道的信息**：
  - `channel`：`search`（已知品类 → Google）还是 `discovery`（新奇品 → Meta/TikTok），
    直接对应正文步骤 3 的渠道分流
  - `risk_flags`：battery / liquid / magnet / fragile / sizing / complex_electronics —
    零备货模式下这些是硬伤，上架前就该看到
- 明令禁止编造认证、保修、品牌、产地；源数据没有的规格宁可不写
- 系统提示词加了 `cache_control`，批量跑几百个 SKU 时省 token

> ⚠️ 当前仅验证了提示词组装与确定性拼接（`--dry-run`），**未做过真实 API 生成** ——
> 本地装好 SDK 与 key 后先 `--limit 3` 验证输出质量再放量。

现金、货代与清关关系、KEBS/KRA 合规、本地配送与客户信任、winner 的本地实拍素材、

## 术语：落地成本

**落地成本 = 一件货送到肯尼亚客户手上之前，你为它付出的全部采购与物流成本。不是 1688 标价。**

| 组成 | 示例（¥175 / 0.8kg） | 说明 |
|---|---|---|
| 货值 | 3,238 KES | ¥175 × 18.5 |
| 国内快递 | 148 | 1688 供应商 → 中国转运仓 |
| 验货 / 转运 | 65 | 开箱验货、换外箱、贴单 |
| 跨境运费 | 1,565 | 首重 + 续重 |
| 税费 | 0 | 双清包税线已含；正规清关则需单算关税 + VAT + IDF + RDL |
| 肯尼亚拆包重打 | 80 | 集货大包裹拆分、分拣、重新打包 |
| **落地成本** | — | 运费按集货 $12/kg 线性计，**以计费重（含体积重）计算** |

**不包含**广告费、最后一公里配送、M-Pesa 手续费、客服、退款预留 —— 那些是每单变动费用，从毛利里再扣。

```
售价 − 落地成本                        = 毛利     (12,000 − 5,016 = 6,984)
毛利 − 广告/配送/支付/客服/退款预留      = 贡献额   (6,984 − 3,330 = 3,654)
```

**贡献额才是真正进口袋的钱。** 本文档中"加价 3 倍""落地成本 ≤ 售价 35%"等规则，
分母一律是**落地成本**，不是 1688 标价。按 1688 标价加成会严重低估售价。

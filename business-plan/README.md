# 肯尼亚跨境电商 —— 商业计划评审与修订

模式约束（用户设定）：**不做 COD，全额预付；本地不备货；只做跨境；类似一件代发。**

---

## 一、原计划的核心问题

原计划的选品标准（速卖通有销量、图 ≥6 张、详情图 ≥10 张、有好视频、售价 ≥2,000 KES、
1688 有货且加 40% 毛利后价格与速卖通持平或更低）存在三个结构性问题：

### 1. 全部是供给侧信号，没有需求侧信号
标准问的是"这个商品好不好拍、好不好上架"，没有一条问"肯尼亚人现在买不买"。
图好看的滞销品到处都是。

### 2. 40% 毛利在任何一种付款模式下都不够
- COD 模式：RTO（拒收）20–35%，每个拒收单亏广告费 + 双程运费。RTO 超过约 22% 时 40% 毛利归零。
- 预付模式：冷流量转化率只有 COD 的 1/3–1/5，CPA 上涨 2–4 倍，把省下的 RTO 全吃掉。

**亏损只是从 RTO 搬到了 CPA，没有消失。**

### 3. 定价规则在一件代发结构下算不出来
一件代发的跨境运费是"首重 + 续重"结构，不是线性 $/kg。
按一件代发拿的是零售价、按票付首重，**运费可能是有规模的跨境卖家的 3 倍**。
样例：¥175 采购 / 0.8kg 的商品，落地成本即 8,000 KES —— 要卖到 12,000 才有 30% 贡献毛利率。
（注：初版据此判定"打不过速卖通"，见下节修正 —— 成本结论成立，但速卖通并非肯尼亚的比价基准。）

## 二、竞争参照系（已修正）

**修正**：初版评审以速卖通为主要参照系和竞争者，这个前提是错的 —— 速卖通在肯尼亚渗透率低，
并非本地消费者的默认比价对象。

- **成本结论不变**：一件代发的落地成本由"首重+续重"的运费结构决定，与速卖通无关。
- **对标价格改变**：基准不是速卖通价，而是**肯尼亚本地零售价**（常见为中国落地成本的 2–4 倍）。
- **因此定价空间打开，消费品路线重新成立。**

### 真正的对标：Kilimall

2014 年中国人创立、总部内罗毕、第一家进入非洲的中国电商平台。模型与本计划高度重合：

| Kilimall 的做法 | 对本计划的意义 |
|---|---|
| **坚持先付款再发货**（不同于其他平台的 COD） | 验证"全额预付"在肯尼亚可跑通 |
| Global Shopping：跨境代购直发肯尼亚 | 与本计划的消费品路线相同 |
| Kilibusiness：肯尼亚买家从中国批量采购 | 即下文路线 B，需求真实存在 |
| **同时建了"非洲海外仓"**（中国商家先发货到非洲仓，本地下单就近发货） | **最重要的信号，见下** |

> 一个模型几乎相同的公司跑了十年后加了备货 —— 大概率因为跨境直发的交付时长在消费品上撑不住。
> **零备货是必须主动管理的最大风险，不是可忽略的约束。**
> 折中路径：零备货起步（一件代发即低成本测试机制）→ **winner 转本地备货**。

### 战略问题已改变

不再是"凭什么比速卖通强"，而是 **"凭什么比 Kilimall 强"**。
它有 1,000+ 服务站覆盖肯尼亚/乌干达/尼日利亚、摩托车配送、佣金 5–15%，
且与你同一条供应链、规模更大。**答案不可能是物流或价格。** 只剩两个方向：

1. **垂直 + 专业度** —— 它是大而全的货架平台；你做单一垂直，懂产品、能咨询、能售后。平台做不了深度。
2. **策展 + 内容 + 私域** —— 它是搜索框；你是"我帮你选好了"。靠 TikTok/WhatsApp 建立人对人信任。

注意：这两个方向恰恰都是 AI 帮不上核心忙的地方（产品知识、售后、人格化信任）。
**AI 放大定位，不创造定位。**

## 二之三、定位：品类缺口

**市场观察**：Kilimall 的跨境商品并不多 —— 计划中要卖的很大一部分，其平台上没有。

这给"凭什么比 Kilimall 强"一个具体答案：**品类覆盖**。你能触达整个 1688 长尾，平台只铺了很窄一条。

并且该定位连带解决了本文档前面标记的两个最大问题：
**当客户在肯尼亚找不到替代品时，预付阻力和价格敏感度同时大幅下降。**
无比价对象 → 65–70% 毛利可达成；无替代选择 → "先付款等 14 天"从"凭什么信你"变成"只能这样"。

### 但必须先答对这个判断题

"平台上没有这个品"有两种相反解释：

- **A. 供给缺口** —— 供给链路够不到：SKU 太长尾、需要选品判断、单量小到平台不愿铺类目。**→ 机会**
- **B. 需求缺口** —— 在肯尼亚根本卖不动。**→ 陷阱**

不可忽视的先验：Kilimall 在肯尼亚跑了十年，有销售与搜索数据，知道什么卖得动。
**它没铺的品类里，B 的占比不低。**

支持 A 的理由：**平台经济学 ≠ 独立站经济学**。平台需要可规模化的 SKU —— 招商、类目建设、
客服培训的成本，长尾品类摊不平；且平台不做选品判断，靠卖家自行上架，本地中国卖家池有限。

> **真正的机会区间：需求真实存在、但单量不足以让平台专门去做的长尾品类。**
> 这也解释了为何 B2B/设备是最锋利的切口 —— 单价高、单量小、需咨询，平台结构上不适合做。

### 区分方法：Jiji 是最好的探针

**Jiji 供给端零门槛** —— 无需供应链、无需类目审批，有货就能挂。因此它反映的是
**接近纯粹的需求信号**，不受供给能力扭曲。

- Jiji 上有人挂 / 有询价 / 有成交，但 Jumia、Kilimall 上没有 → **强供给缺口信号，最该做的品**
- Jiji 上也一片空白 → 大概率需求缺口，砍掉

交叉验证：

| 探针 | 供给缺口的表现 |
|---|---|
| Google 搜索量（KE） | 有搜索量，但结果全是国外站、无本地卖家 |
| Facebook 群 / WhatsApp 社交电商 | 有人在卖，或有人在问哪里能买到 |
| 本地实体零售 | 有店在卖但贵 2–4 倍（需求 + 价格空间同时确认） |
| 相邻品类 | 相邻品类卖得好、唯独此品空 → 偏供给缺口；整棵类目树都空 → 偏需求缺口 |

**新增硬性排除标准**：Jiji + Google KE + 社交电商三处均无痕迹 → 直接砍掉，
不论其在 1688 上的素材多好看。

## 二之二、待验证的唯一关键指标

在继续修改计划之前，先花 **$300–500** 广告费、用 **5 个品**（选"本地买得到但本地价 ≥ 2.5 倍"的）
测一件事：

> **有多少肯尼亚人会在你的站上用 M-Pesa 先付全款、并接受 14 天交期？**

Kilimall 证明这个数不是零，但它的品牌信任是十年攒的，你是零 —— 必须知道**在你的站上**是多少。

- 转化率撑得住 → 消费品路线放量，winner 转本地备货
- 转化率撑不住 → 改**定金模式**（30–50% 定金 + 到货付尾款，非 COD），或转垂直 B2B（预付是行业惯例）

## 三、建议的两条路线

### 路线 A：本地备货 + 快交付 + 策展

（在修正竞争参照系后，A 与 B 不再互斥；A 可作为 B 或消费品路线跑出 winner 之后的演进方向。）
- 差异化：3 天送达 + 选品 + 本地售后
- 要求：压货、资金、仓库、COD 或预付均可
- 与"零备货"约束冲突

### 路线 B：跨境 B2B / 大件设备

面向肯尼亚小微商户：商用厨房设备、美容院仪器、印刷切割设备、农业加工机械、
健身器械、建材五金等。

| 现有约束 | 在 B2B/大件上的表现 |
|---|---|
| 零备货 | 商业买家接受"下单 → 发货 → 4–6 周"，是行业惯例 |
| 全额预付 | 商业采购本就付 30–50% 定金甚至全款；理性买家 |
| 跨境运费高 | 客单 50,000–500,000 KES，运费占比个位数，甚至可走海运 |
| CPA 高 | 单笔利润数万先令；Google 搜索意图极强 |
| 打不过速卖通 | 速卖通不做此类 —— 运费与售后结构不支持 |
| 打不过本地 | 本地设备商加价常达 2–4 倍且款式陈旧 |

附加优势：**口碑与复购**。一个餐馆老板用得好会告诉另外五个。消费品一件代发没有这个。

代价：需要产品知识、售前咨询、装机/维修支持、销售周期长、订单密度低。
**但这些正是壁垒 —— 因为难，所以没人做。**

### 若坚持消费品路线，唯一活法
只做"速卖通上有、但肯尼亚人搜不到 / 不敢买 / 挑不出来"的高客单品（≥12,000 KES），
靠内容和 WhatsApp 建立信任，明确定位为代购。
天花板取决于内容能力，不是供应链能力。

## 四、修订后的选品标准（消费品路线）

原标准中的"图 ≥6 张、详情图 ≥10 张、有好视频"应从**准入标准降级为加分项** ——
它决定投放成本，不决定这个品能不能卖。

1. **本地买不到，或本地价 ≥ 中国落地成本 2.5 倍**（最重要，取代"图片好看"）
1b. **且需求信号已被证实**：Jiji 有挂牌/询价，或 Google KE 有搜索量，或社交电商有交易痕迹。
    三处均无痕迹 → 直接砍掉（区分供给缺口与需求缺口，见第二之三节）
2. 售价 ≥ 12,000 KES（消费品路线）—— 基准是**肯尼亚本地零售价**，不是速卖通价
3. 运费占售价 ≤ 12%（按首重+续重实算，不是线性 $/kg）
4. 加价 ≥ 2.9 倍落地成本（毛利率 65–70%），定价对标**本地零售价的 60–80%**
5. 低故障率：不易碎、无尺码、无活动部件、非复杂电子（零备货 = 无法换货）
6. 类目可过关：无电池/液体/磁铁/仿牌；KEBS PVoC 可覆盖
7. 1688 有 ≥2 家可用供应商（单一供应商不做）
8. 需求信号：KE 地区 Google 搜索量 + Jumia/Kilimall 评论数 + Meta 广告库投放时长
9. （加分）图片/视频素材质量

## 五、运营要点（无论哪条路线）

### 链路：别让 1688 供应商直发出境
```
1688 一件代发 → 中国转运仓（开箱验货拍照 + 换外箱 + 贴单）→ 跨境专线 → 肯尼亚最后一公里
```
零备货意味着转运仓是**唯一的品控检查点**。供应商直发 = 把品控彩票寄给已付款客户，
14 天后才知道开出什么。转运仓 ¥2–5/件，是刚性成本。

### 头号风险：相关性风险
零备货 + 预付模式下，问题不会一个一个来，会一批一批来：
- 一票货扣关 → 同批几十个已付款客户同时要退款，而货款运费已付
- 供应商发错版本 → 14 天后、8,000 公里外才发现，无本地库存可换

对策：养 2–3 条货代线；中国端强制验货；预留 **5–8% 赔付准备金**。

### 交付承诺工程化
- 固定发运班期（每周两班），结账页显示**具体日期区间**而非"10–15 天"
- 每 3 天一条 WhatsApp 进度推送 —— 多数退款要求源于焦虑而非不满
- 同客户 48 小时内订单**自动并单**（一票只付一次首重，是实打实的运费套利）

### 获客
冷流量直接进结账页在预付模式下转化极低。可行的两条：
1. **Google Search / Shopping** —— 高意图流量，与预付模式最匹配，权重应高于 Meta
2. **广告 → WhatsApp → 对话 → M-Pesa 付款链接** —— 信任在对话里建立，不在落地页上

### 技术优先项
WooCommerce 接 **Daraja API STK Push**。若当前是"转账到 Paybill 再粘贴交易码"，
这一步在流失大量已决定购买的客户。

## 六、扩量公式

> **月利润 = 每月测试数 × 中签率 × 单个 winner 的生命周期利润**

一件代发的最大战略价值：零 MOQ、零压货，把第一个乘数的资金约束几乎去掉 ——
**可以同时测 50 个品而不是 5 个**，瓶颈只剩广告测试预算。

- 提高测试数：固定小额预算（$60–100 / 3 天）+ 固定模板 + 固定 kill 规则，**并行测不要串行测**
- 提高中签率：需求侧信号 + 把自己的历史 winner/loser 数据回灌到打分模型
- 提高 winner 深度：提价测试、组合装（同时是运费套利）、多渠道、**WhatsApp 私域复购**

## 七、AI 能接管的部分

### 首要应用：品类缺口扫描器

若核心竞争力是"覆盖别人没有的品类"，则核心能力是**发现缺口的广度与速度** ——
这是 AI 唯一能提供数量级提升的环节。**它比改写标题、生成素材重要得多。**

```
1688 类目批量抓取（候选池，数万 SKU）
   ↓ 硬过滤（价格 / 重量 / 类目黑名单 / 价值密度）
   ↓ 供给侧反查：Jumia / Kilimall / Jiji / 本地零售 —— 有没有人在卖？多少钱？
   ↓ 需求侧反查：Google KE 搜索量 / Jiji 挂牌与询价 / 社交电商痕迹
   ↓ 打分：需求信号强 × 本地供给弱 × 落地成本可行 × 低故障率
   ↓ 输出：Top N 缺口品 + 逐个落地成本与建议售价（接 tools/unit_economics.py）
```

手工一天能查 20 个品；自动化后一天可扫 2,000 个。

**复利效应**：运行一段时间后积累"哪些缺口品真的卖动了"的历史数据，回灌打分模型，
中签率持续上升。**这是平台模式拿不到的数据。**

### 其余环节

**可自动化 ~70%，但自动化的是执行，不是判断。**

| 环节 | 自动化程度 | 说明 |
|---|---|---|
| 采集 | 高 | 优先官方 API（速卖通联盟/DS API、1688 开放平台图搜），纯爬虫有 ToS 与封 IP 问题 |
| 硬过滤 | 高 | 价格/重量/类目黑名单 —— 是规则，不需要 AI |
| 图片视频质量判断 | 高 | 多模态打分、水印检测、主图与详情一致性 |
| 1688 反查比价 | 高 | 图搜找同款 → 多供应商比价 |
| 落地成本与定价 | 高 | 见 `tools/unit_economics.py` |
| "肯尼亚人会不会买"打分 | 中 | 需用自己的历史数据 few-shot 校准，否则是瞎猜 |
| 上架（标题/规格/SEO/图片/写入 WooCommerce） | 很高 | 一人 + 脚本一天 200–500 SKU |
| 广告素材与文案 | 中 | 适合第一轮测试；winner 必须换本地实拍 UGC |
| 投放杀/放量决策 | 高 | **用确定性规则引擎，不要用 LLM 决策** |
| WhatsApp 成交与客服 | 高 | 预付模式下 WhatsApp 是成交渠道不是客服渠道，ROI 最高 |

**AI 做不了的（也就是真正的护城河）**：现金、货代关系与清关、COD/配送商谈判、
退货处理、KEBS/KRA 合规、本地客户信任、winner 的本地实拍素材、B2B 路线的产品知识与售后。

> AI 能把"每周测 3 款"变成"每周测 30 款"，成本几乎不变。
> 但它不解决毛利率、交付确定性和定位问题 —— 而那三个才是生死线。

## 工具

```bash
python3 tools/unit_economics.py                                    # 内置示例
python3 tools/unit_economics.py --cost-cny 175 --weight 0.8 --sweep
```

输出落地成本拆解、毛利/贡献毛利、**盈亏平衡 CPA**、达到目标贡献率所需售价，
以及售价敏感性表。所有汇率与费率为占位默认值，**第一次使用前必须用真实货代报价、
M-Pesa 费率、实际 CPA 和退款率替换**（见 `tools/unit_economics.py` 中的 `Assumptions`）。

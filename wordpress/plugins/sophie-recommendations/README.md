# Sophie Recommendations – Products For You

WooCommerce 个性化推荐插件：在首页显示 **"Products For You"**，每位访客看到的商品不同；同时改进商品页底部的 **Related products**。

## 安装

1. 把 `sophie-recommendations.zip` 上传到 **插件 → 安装插件 → 上传插件**，然后启用。
2. 启用约 30 秒后会自动完成第一次学习（也可以在 **WooCommerce → Recommendations** 点击 **Rebuild now**）。
3. 在首页编辑器中添加一个 **Shortcode（短代码）** 元素：
   ```
   [sophie_for_you]
   ```
   也可以指定参数：`[sophie_for_you title="Products For You" limit="8" columns="4"]`
   Elessi 主题使用的 WPBakery / Elementor 都有 Shortcode 元素。

## 算法

**每晚 03:00 学习一次（WP-Cron，约几秒钟）**
- **一起购买**：同一位顾客一年内买过的商品（读取 WooCommerce Analytics 数据表；表为空时直接读订单）。越近的订单权重越高。
- **一起浏览**：同一次浏览中看过的商品（匿名记录，最近 60 天）。订单数据往往很少，浏览数据能大大提升覆盖面。
- 相似度 = 共现的余弦相似度 + 收缩修正：只出现过一次的巧合组合不会被当真，畅销品也不会和所有商品都"相似"。
- 购物篮过大（例如一次买 40 件不相关的商品）会自动降权。
- 每个商品保留最相似的 30 个商品。

**每小时更新"趋势"**：最近的销量（约 14 天衰减）+ 最近的浏览量 + 历史销量 + 新品加成。

**每位访客实时计算（约 10 毫秒）**
1. 浏览器记住访客最近看过和加入购物车的 20 件商品，以及买过的商品（只存在访客自己的浏览器里）。
2. 越近看过的商品权重越高，每件商品的"相似商品"分数会先归一化，避免某个商品的强关联盖过最新的兴趣。
3. 再结合访客常看分类中的热门商品，以及全站趋势。
4. **多样性重排**：同一分类的商品越多，后续同类商品得分越低，避免 8 件几乎一样的商品。
5. 每天有少量变化，同一天内保持稳定。
6. 已经看过、已经买过、缺货、隐藏的商品不会出现；售罄的商品会立即消失，不用等到晚上重新学习。
7. 新访客（没有任何记录）：显示多个分类的当前热门商品。

## 性能（和网站共用服务器时很重要）

- 首页 HTML 不变，可以继续被页面缓存和 Cloudflare 缓存。推荐区域在**滚动到附近时**才通过一个小请求加载，并预留占位，页面不会跳动。
- 推荐请求只由 URL 决定（URL 中包含浏览记录），设置了 `Cache-Control: public, s-maxage=3600`：新访客共用同一个 URL，可以被缓存。
- 未命中缓存时，服务器只需执行几条带索引的查询：实测约 10 毫秒计算，加上渲染 8 张卡片的完整请求约 45 毫秒。
- 浏览数据**每 3 次商品浏览才发送 1 次请求**；搜索引擎爬虫的请求会被忽略。
- 晚间学习写入新表后再一次性原子切换，不会锁住网站。实测 4,000 件商品、5 万个订单、30 万次浏览：约 6 秒，约 95 MB 内存。内存超过 PHP 上限的 70% 时会自动停止读取更多数据，不会导致网站崩溃。
- 浏览记录只保留 90 天，自动清理。

## 隐私
浏览器中只保存一个随机数字和商品 ID，不保存姓名、电话、邮箱或 IP。建议在隐私政策中加一句："我们会匿名记录商品浏览，用于改进商品推荐。"可以在设置中关闭"Learn from browsing"（关闭后只使用订单数据）。

## 后台：WooCommerce → Recommendations
- 模型状态：学习时间、覆盖了多少商品、使用了多少订单和浏览会话。
- **Preview**：输入几个商品 ID，模拟"看过这些商品的访客"会看到什么推荐，以及推荐理由（一起购买/浏览、所在分类热门、全站趋势）。
- 设置：标题、商品数量、列数、是否学习浏览数据、是否改进 Related products、排除的分类。

## 给 App 使用的接口
- `GET /wp-json/sophie-rec/v1/for-you?h=12,34&p=56&n=8` → 推荐商品 ID 列表
- `GET /wp-json/sophie-rec/v1/similar/123?n=8` → 相似商品
